没有新的代码改动时不要重跑测试套件，包括"为了核实摘要里的数字"或"换几个 Node 版本再确认一遍"这类理由。改了代码之后，跑和改动相关的那一组，收尾时整套跑一遍就够。

**Why:** 2026-10-13 对话压缩后接着干活，agent 一上来先在两个 Node 版本上重跑全部测试，被用户打断："别跑测试了，咋啥都没干就一直跑测试，压缩对话前都跑过很多遍了，别浪费时间"。

**How to apply:** 接手被压缩过的对话时，摘要里记着的验证结果当作已有的证据；哪条没验到就在汇报里照实写"没在某某上重跑"，而不是先去补跑。让用户等着的时间优先花在用户要的事上。（"收尾时整套跑一遍"是 agent 的理解，用户只说了不要无故重跑。）
