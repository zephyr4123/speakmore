# 风格纲领：乐段驱动的动态排版发布片

2026-10-23 用户在抖音看到一支宣传片，原话："这个视频最好的点是音乐+转场动效果"。用户要求把风格固化成纲领："丢给新的对话或者另外一个 AI，它也能做出一样的效果"。第三支（三位一体）照这份做，见 [[speakmore-promo-video]]。

**Why:** 压缩对话后分析过程会丢，这份纲领是第三支唯一的风格依据。
**How to apply:** 动手做第三支前先通读一遍。第七节列的冲突项，要先让用户拍板。第八节的验收要真的跑。

参考片和分析材料都在本仓库的 `.playwright-mcp/promo3-ref/`，不进 git。片子本身是 `gemini-launch-ref.mp4`（1920×1080，30 帧，73.84 秒）。

---

## 一、总纲

> **用一首段落分明的快歌当剧本，文字当主角，产品界面当证据。**
> 全片的字幕连起来读是一段完整的宣言。拆成一到四个词一组，每组配一个专属动作，字怎么动由字的意思决定。
> 镜头一刻不停，转场是上一个动作的延续，很少硬切。
> 大转折只落在音乐的段落交界上，段内的节奏靠持续的运动和逐词出字填满。
> 分明、暗两幕：亮幕讲"已有的、日常的"，暗幕讲"更强的"。片尾音乐一刀停住，标志在静音里出现。

八条纲领：

1. **音乐先行。** 先选曲、标出段落交界，再按音乐排分镜。不能先剪画面再配乐。
2. **文字是主角。** 没有旁白、没有人物，信息全靠屏幕上的字。一屏只放一个词组。
3. **字义驱动动效。** 每个词组的动法要把它的意思演出来：说"翻开下一章"，就真的翻页；说"更多"，字就被拉长；说"头脑风暴"，就是一场字的风暴。
4. **界面是证据。** 每讲一项能力，紧跟一段真实界面的操作。界面斜放在三维空间里，像一块悬浮的玻璃板。
5. **镜头一刻不停。** 每个画面都有缓慢的推、移、转作为底速；一两秒就出现一个新动作。
6. **转场是动作的延续。** 推穿、钻入、翻页、甩入、卷入、粒子化，都让上一个画面的运动直接把观众带进下一个画面。
7. **段落级卡点。** 大转折和音乐段落交界对齐，误差在一两帧以内；段内不追着每一拍剪。
8. **克制的色彩，两幕的光。** 品牌渐变色只给关键词和标志用；亮幕是淡雾浅底，暗幕是深紫黑底加霓虹描边；结尾是静音加标志。

## 三、音乐

### 选曲标准

- 快歌，约 120–160 拍/分（参考片测得约 152）。要有明确的人声或旋律记忆点，参考片是女声反复唱 "I want that new thing / gimme some of that"。
- 段落必须分明，至少要有：
  - 前奏；
  - 两次以上"抽空→砸下"；
  - 一段低音整段抽掉的过门；
  - 硬停的结尾，可以带一句清唱尾音。
- 不加独立音效。两次盲听的结论一致：参考片里没有单独的嗖声、撞击声、点击声，强调全靠音乐自己的抽空和重拍。

### 参考片实测的段落（低音指 30–150 Hz 的能量）

|---|---|---|

| 14.5 | 重拍砸下，人声进 | 粒子漩涡把黑底冲成白底，重组成新标志 |
| 27.5–31.5 | 间奏，鼓和低音变稀 | 过渡短句、字的扭曲、手机甩入 |

### 原曲与参考片的剪法（10-23 实测）

- 配乐就是 Midnight Riot《That New Thing》。用户买了单曲（网易云），已登记进 kineto，第三支的素材名是 `song`。
  - kineto 里登记的授权是"未取得公开发布授权"，照实登记就行；用户 10-23 说只是拿来配乐、不商用，别再跟用户提授权。
  - 原曲 196.3 秒，150 拍/分整（一拍 0.4 秒，60 帧下 24 帧），第一拍在 0.4225 秒。
- **参考片的配乐是剪拼出来的**，不是从原曲某处整段放下来。按半秒一段和原曲做互相关，对出来是这样（参考片秒 → 原曲秒）：
  - 0–12.2 → 0.36–12.6：前奏。
  - 12.2–14.4：对不上，可能加了效果或在过渡。这一段正好是翻页到"Today"、"Bard is becoming"。
  - 14.5–26.3 → 53.26–65.06：第一次砸下就是原曲 53.22 秒（第 132 拍）。之前 52.0–53.2 秒是原曲自带的三拍低音抽空。
  - 26.5–31.2 → 78.1–82.8；31.5–38.2 → 103.9–110.6；38.5–41.7 → 123.7–126.9；44.5–46.5 → 62.5–64.5（这段对得不太稳）。
  - 47.5–55.9 → 126.3–134.7。其中 50.5–55.5 相似度掉到 0.2–0.4，多半是剪辑时加了滤波，把低音抽掉做成过门（未验证）。
  - 57.5–70.5 → 181.1–194.1：直接用原曲真正的结尾，最后一句清唱也是原曲自带的。
- **结论（写进纲领的做法）**：先按画面需要的长度和转折，在原曲的拍点上剪拼段落。过门可以靠滤波人为做出来。结尾用原曲的真结尾。
- 冒烟片从原曲第 122 拍（49.22 秒）起放，第 10 拍（片子第 4 秒）就是那一下砸下。

### 卡点规则

- **段落级卡死。** 大转折的第一帧落在段落交界或重拍上，误差不超过两帧。
- **抽空→砸下。** 交界前约半拍到一拍，音乐先把低音抽掉，画面在这个空当里做预备动作（消散、钻入、收拢）。新画面的第一帧落在重拍上。全片用三次左右，留给最重要的转折。
- **段内不逐拍剪。** 实测参考片画面变化最大的几十个时刻，落在拍点前后 80 毫秒内的只占约四成，和随机撒点差不多。段内靠持续运动和逐词出字跟着音乐走。逐词出字可以大致落在四分或八分音符上，但不强求。
- **过门对应换幕。** 低音整段抽掉的那一段，正好用来换幕（亮转暗）、蓄力。
- **结尾。** 音乐硬停，然后清唱尾音，然后静音。标志在静音里出现，静止至少 1.5 秒。

## 四、文字（动态排版）

### 字形和排布

- 全片只用一种无衬线字体（参考片用 Google Sans），中等字重，居中，四周大量留白。
- 字号跳变很大（目测）：普通词组约占画面高度的 3–4%，关键词和品牌名约 7–10%，相差两到三倍。
- 颜色：普通字在亮幕用黑、在暗幕用白；只有关键词上品牌渐变色（参考片是蓝→紫→粉），一屏最多一处。
- 入场常带虚实变化：字从虚焦、偏大的状态收成清晰的正常大小（"Introducing""Our most capable AI"）。

### 手法词汇（按字义挑，相邻两句不重复）

|---|---|---|---|

| 字母波浪 | 0.8–1.9 | 单词里的字母上下错落，起伏一次后归位 | experimenting（试验中、不稳定） |

## 五、界面、镜头与转场

### 界面（证据）

- 用真实产品界面，干净的截图或照真界面重画。界面斜放在三维空间里（绕横轴和竖轴各转十几到二十几度），带柔和投影和细细的渐变描边，像悬浮的玻璃板。
- 一次只讲一个交互：
  1. 先特写输入：只拍输入框，逐字打出；
  2. 再拉远看全貌：镜头退开，露出整个窗口；
  3. 结果流式出现：一行一行长出来。
- 卡片、建议项在空间里依次浮现，有前后层次。
- 设备（手机、窗口）只画干净的轮廓，没有人、手、桌面实拍。全片唯一的照片是用户传给 AI 的一张狗的照片，属于界面内容。

### 镜头

- 永远有底速：慢推、慢移、缓慢旋转，没有完全静止的画面（落版和收尾标志除外）。
- 一两秒出现一个新动作，单个镜头通常不超过三秒。
- 运动曲线快进慢停（强指数缓出）。甩入的物体带一点回弹，快速运动加运动模糊，前景和背景用景深虚化拉开空间。

### 转场（按使用频率）

1. **动作延续型（主力）**：推穿字、钻进屏幕、甩入回弹、翻转、螺旋卷入。上一个画面的运动直接变成下一个画面的入场。
2. **换幕型（各一次）**：
   - 翻页：亮→暗，"下一章"；
   - 粒子化：暗→亮，第一次揭幕；
   - 冲进菜单后黑色从四周收拢成圆：亮→暗，第二次揭幕。
3. **硬切（少量）**：只用在同一段落里关系紧密的两个画面之间，而且切在重拍上（界面→文字墙、图标→输入框）。
4. 一个手法最多用两次。粒子化、螺旋这类重手法只留给揭幕。

### 光与色

- **亮幕**：近白底，上面有极淡的蓝、粉、薰衣草色模糊光斑缓慢流动，像雾。
- **暗幕**：深紫黑底，带若有若无的渐变；界面和圆环用蓝紫粉霓虹描边、边缘发光。
- **品牌渐变**：只出现在关键词、标志、描边上。其余全是中性色。

## 六、禁忌

- 不配旁白，不加独立音效，不堆滤镜。
- 不出现人脸和人物实拍。
- 一屏不放两句话，不用大段正文。
- 段内不逐拍硬切。一拍一切会显得像音乐短视频，不像发布片。
- 相邻两句不用同一种字的动法。
- 不换字体，不在非关键词上用彩色。

## 七、套用到 SpeakMore 第三支：已经定死的规矩，和待用户拍板的冲突

**定死的规矩**（来自前两支，见 [[speakmore-promo-video]]）：

- 字幕是中文书面语。
- 字幕不带人称：参考片的 "You've been…" 不能照搬，改成只陈述事实。
- 不用合成人声。
- 转场不用闪白。参考片 14.4→14.5 粒子漩涡从黑冲到白，属于亮度骤升，照做前要控制亮度上升：沿用第二支的测法，三帧内平均亮度的最大升幅不超过 50 左右。
- 代码画的界面走"精密仪器"观感。
- 素材经 `./kineto asset add` 登记，导出用 `./kineto render`，收尾跑 `npm run verify`。

**中文的处理**：字的动效以单个汉字为单位，逐字、逐词组出现都成立。字母波浪、打散重组、拉伸（比如"更多"的"多"拉长）都能照做。

**可以直接对上的地方**（供讨论，没定）：

- "口述成文"天然就是"打散重组"：口头禅散掉，成文落下。第一支开场已经这样演过。
- "划词即译"：选中加高亮，然后译文从选区里长出来，对应"打字加选中"那一招。
- 三项功能可以对应"能力 A、能力 B、高潮"三段，用"抽空→砸下"切换。

**待用户拍板的冲突**（动手前用选项问）：

1. **背景**：参考片是抽象的淡雾底。前两支用的是用户自己的真屏幕截图（当时用户说"背景不要纯黑"，要能看出是 Mac 桌面）。第三支用哪种，还是两者结合？
2. **音效**：参考片完全没有。前两支都加过（第二支用户说别用沙子声、别用太重的低鼓）。这支是否全靠音乐？
3. **配乐**：需要一首段落分明的快歌（前奏、两次抽空→砸下、低音全抽的过门、硬停加清唱）。前两支是用户提供的曲子，这次是否照旧由用户提供？（已定：用户买的 Midnight Riot《That New Thing》）
4. **时长**：参考片 74 秒，前两支是 88 秒和 103 秒。
5. **两幕怎么分**：参考片是"免费版亮、高级版暗"。SpeakMore 是三项功能平级（[[speakmore-two-pipelines]] 里"平级、不分主次"的精神），暗幕给谁，还是三项各一种光？

## 八、可量化的验收（对自己的成片跑）

工具在 `.playwright-mcp/promo3-ref/tools/`（Python 先建 venv：`python3 -m venv .venv && .venv/bin/pip install librosa matplotlib`）：

- `beats.py <wav> <ydif.txt> <输出目录>`：算节拍、起音、各频段响度，和每帧画面变化量画在同一条时间轴上，输出 `timeline.png` 和 `beats.json`。
  - 每帧变化量这样取：`ffmpeg -i 片子.mp4 -vf "scale=240:-1,signalstats,metadata=print:key=lavfi.signalstats.YDIF:file=ydif.txt" -f null -`
- `strips.py <视频> <windows.json> <输出目录>`：把指定时间窗逐帧拼成条，帧上标时间。可以和参考片的 `strips/` 并排比较。
- `listen-audio.mjs <mp3> <模型> <输出>`：让 Gemini 盲听音频，用 `scripts/dev/with-key.sh gemini node …` 跑。
  - **教训**：把整段视频发给 Gemini，它收不到音频（用量统计里只有 VIDEO，没有 AUDIO），描述的音乐是照着画面编的。必须单独发音频，并核对用量统计里有 AUDIO。
  - 两个模型的说法要互相印证，再用实测数据校正时间点。

验收项：

1. **段落卡点**：分镜表每一行写明对应的音乐时刻。成片里每个大转折的第一帧，与所选曲子实测的段落交界相差不超过两帧。
2. **镜头不停**：除落版和收尾标志外，没有连续两秒以上每帧变化量几乎为零的片段。
3. **不闪白**：三帧内平均亮度的最大升幅不超过 50 左右（满值 255）。
4. **结尾**：音乐停后至少 1.5 秒静音，标志静止。
5. **手法不重复**：分镜表加一列"手法"，相邻两行不能相同，重手法各用一次。
6. **逐帧对照**：转场处用 `strips.py` 拼条，和参考片的拼条并排看，节奏和完成度要接近。
