SpeakMore 现在只有用户自己在用。用户 2026-10-14 的原话："现在是没有用户的，只有我在用，因为都还是在内测"。

**Why:** 那之前 agent 按"已经有一批使用者"来设计：给 0.3 留退路（Gemini 的设置只存模型名、退回 0.3 前先换回 Gemini）、拦下 0.3 的旧后台、写"普通用户碰不到、开发者才会碰到"之类的分析，还在汇报里反复提。对一个人的内测来说这些是多出来的复杂度和话。

**How to apply:**
- 破坏性变更照样要有办法回去（AGENTS.md 红线），但按"用户一个人、知道发生了什么"来定规模：一句说明或者让用户重装一次通常就够，不必为旧版本写兼容层。已经写好的兼容代码不用专门去删，碰到要改时顺手简化。
- 汇报里少讲"别的使用者升级会怎样"；要讲的是用户自己这台机器上会怎样。
- 这一条和"按真实产品打磨"不冲突（[[typeless-clone-as-real-product]]）：面向用户的环节照样做到位，省的是为不存在的存量用户做的兼容。等用户说开始给别人用了，这一条就作废，改回按有用户来考虑。
