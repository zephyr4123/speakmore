审查（外部 PR、自己的改动）除了功能对不对，还要审简洁度：有没有能删的、能并的、绕远的，改动量和它带来的东西配不配。

用户原话（10-30 审 #19、#20 时）："不只是功能审，简洁度也要审核的，要有工程审美，不然会越来越臃肿"。

**Why:** 外部贡献照着现有写法铺开，每个 PR 都"合理"，合起来就越来越胖；#18 改了 190 多行，用户当时就要求精简后再合。

**How to apply:**
- 每个 PR 的结论里单列一项简洁度：哪些可以删、哪些可以换成更短的做法、哪些是照惯例必须的，给出精简前后的行数。
- 能用现成的库或已有的机制解决的，不手写；能生成的不手维护（如 #20 的繁体文案改成从简体自动生成）。
- 贡献者为了绕开一个小问题改了既有原则的（如 #20 把语言名字改成按界面语言写），默认退回原则，说明理由。
